# Правила проекта (никогда не нарушать)

1. **Никогда не выполнять физический `DELETE`.** Удаление записи — это всегда
   `UPDATE ... SET status = 0` (в `shipments` — поле `is_active`, т.к. `status`
   там занят под стадию рейса). Данные не удаляются из БД физически.

2. **Удаление одной записи не должно затрагивать другие записи.**
   Все внешние ключи — `ON DELETE RESTRICT`. Никаких `ON DELETE CASCADE`
   и никакой логики в коде, которая бы каскадно проставляла `status = 0`
   у связанных записей.

3. **Выборки по умолчанию показывают только активные записи**
   (`status = 1`, для `shipments` — `is_active = 1`), если явно не запрошено
   иначе (например, экран "корзина"/архив для восстановления).

4. **Все финансовые операции — в транзакции.** Создание/изменение
   `payments`, `expenses`, `cargo.final_cost` — через `BEGIN/COMMIT/ROLLBACK`,
   без промежуточных состояний.

5. **Все внутренние расчёты — в USD.** `amount_usd` в `payments`/`expenses`
   фиксируется в момент операции по курсу на эту дату и никогда не
   пересчитывается задним числом при изменении курса.

6. **Распределённый/оставшийся вес и объём рейса не хранятся отдельно.**
   Только `SUM(cargo.weight_kg / volume_m3)` по `shipment_id` на лету —
   никогда не дублировать и не кэшировать это значение в `shipments`.

7. **`shipments.status` (стадия рейса) и `shipments.is_active` (soft-delete)
   — разные поля.** Не путать и не объединять.
